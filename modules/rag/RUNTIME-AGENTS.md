# Runtime collaboration-analysis agents (Phase 09, rag-engineer)

Package `scholarchain.rag.runtime` in `modules/rag`. `rag` depends on `core` only. Stages talk to core ports: `GraphStore`, `KeyValueStore`, `VectorStore`, `ObjectStore`, `Embedder`, `ModelClient`. No storage, Spark, Hadoop or entity-resolution type is imported. No AWS, Bedrock, Anthropic or Voyage call is made anywhere in this phase; the Bedrock and Anthropic clients are compiled but never invoked, and local runs use `FakeModelClient`.

## 1. Architecture

`QueryWorkflow.create(settings, model, kv, graph, vectors, objects, embedder, prompts, tables, clock, llmVerification)` composes the stages. `run(QueryRequest(question, StructuredConstraints))` returns a `QueryOutcome`.

| # | Class | Role |
|---|---|---|
| 1 | `QueryPlannerAgent` | question + constraints to a validated `QueryPlanV2`; model proposes, code validates; rule-based fallback (`ruleBased`) |
| 2 | `ResearcherResolverAgent` | names/IDs to `ResolvedResearcherCandidate`s; abstains on ambiguity |
| 3 | `CollaborationMetricsAgent` | exact stored metrics, window summary, rankings, temporal changes |
| 4 | `PathFinderAgent` (`GraphAgents.scala`) | `neighbors`, `coauthor-edge`, `shortest-path` templates; hops with weight, works, years, provenance |
| 5 | `CommunityAnalystAgent` (`GraphAgents.scala`) | `component`, `community` templates, degree-vs-bridge fact |
| 6 | `SemanticContextAgent` | vector search to `SemanticContextItem`s (semantic-only drafts) |
| 7 | `EvidenceBuilderAgent` | bounded `EvidenceBundle`; returns `EvidenceSet` keeping graph and semantic IDs apart |
| 8 | `AnswerSynthesisAgent` (+ `TemplateSynthesizer`) | `ProposedClaim`s with evidence IDs and structured assertions |
| 9 | `ClaimVerificationAgent` | deterministic checks first; optional LLM wording check that can only downgrade |
| 10 | `AuditAgent` | persists session, bundle and `QueryAudit` through the ports |

Supporting: `StructuredModelCaller` (the only way stages call a model; budgets, JSON schema validation, bounded retry), `PromptRepository`, `JsonSchemaValidator`, `FakeModelClient`, `BedrockConverseModelClient` + `SdkConverseInvoker`, `AnthropicModelClient`, `ModelClientFactory`, `AnalyticsReader`, `Fact`, `EvidenceDraft`, `BenchmarkResponders`, `BenchmarkGenerator`.

Flow in `run`: write `received` session, plan, resolve (abstain unless every subject resolved to exactly one researcher), collect evidence per planned operation, build bundle, synthesize, verify, compose the answer from claims whose status is `verified` or `partially_supported`, audit, move the session to `answered`, `rejected` (abstention) or `failed`. Abstention reasons: `plan_invalid`, `identity_ambiguous`, `identity_unresolved`, `no_evidence`, `evidence_invalid`, `no_verified_claims`. The query ID is `query:` + SHA-256 digest of the normalized question and the constraints JSON, so a re-run is the same query. The session ID is per run: `session-` + the first 40 hex of the digest of the query ID and the run's start time (`clock.epochMillis()`), so asking the same question again opens a new session that points at the new run's bundle instead of ending in `session_conflict`. Under `RuntimeClock.Fixed` the identities are stable and a repeated run is byte-identical (`unchanged`).

## 2. Guarantees

* **User text never becomes a query or AWS call.** The question is stored as data (`QueryPlanV2.question`, control characters replaced by spaces) and sent to the model only as an untrusted `Data` segment. Researcher names are only compared with stored names. Stages call only the six `GraphTemplates` with typed `GraphValue` parameters (resolved researcher IDs and window labels, bounds clamped to `rag.graph.*`); no query string is built anywhere in `rag`. Unknown operations fail the planner schema (`enum`) and the `QueryOperationV2` parse, and the plan then comes from the fallback.
* **Retrieved text is data.** `ModelRequest.validate` rejects Data in `system`; adapters wrap Data in `<untrusted_data label="...">` with a notice, and `ModelWrapping.neutralize` stops a closing tag inside the text from ending the wrapper. Prompts say titles/abstracts/excerpts may contain instructions and must be ignored. No chain of thought is requested; only the schema-valid JSON is kept; `ModelCall` and `QueryAudit` hold hashes, counts and codes only.
* **Every model output is schema-validated** (`JsonSchemaValidator`, keywords listed in its Scaladoc) before use. Malformed or schema-invalid output is `ModelError.MalformedOutput`, retried at most `min(rag.model.max-malformed-retries, 2)` times, then a typed `ModelFailure` (with its `ModelCall`). Throttled/Unavailable are retried inside the same bound. Budgets: user-segment characters <= `rag.budget.context-characters`, estimated tokens (chars/4) <= `rag.budget.input-tokens`, output tokens capped at `rag.budget.output-tokens`; over budget is `BudgetExceeded` with no call.
* **Graph facts vs semantic context.** Semantic drafts are `TextChunk` evidence with `semantic = true`; the builder places them after graph/metric evidence and records the IDs separately; the verifier lets a claim that cites only semantic items be at best `partially_supported` (`semantic_context_only`) and rejects any number, assertion or window in it.
* **Key handling.** `AnthropicModelClient` reads the variable named by `rag.model.anthropic-api-key-env-var` (default `SCHOLARCHAIN_ANTHROPIC_API_KEY`) through an injected `env` at call time, uses it only as the `x-api-key` header of the transport request, and never puts it in `toString` (`apiKey=<redacted>`), `ModelError`, exceptions or audit. Failures carry a fixed phrase plus an HTTP status class; reply bodies are parsed, never echoed. Bedrock uses injected credentials (no default chain) and the hermetic client configuration; the SDK client is created lazily (`SdkConverseInvoker.clientsConstructed`), and `ModelClientFactory.bedrock` is `Left` unless `liveProfile = true`.

## 3. Stage contracts

**Planner.** `plan(queryId, QueryRequest): PlannerResult(plan: Either[RuntimeError, QueryPlanV2], usedFallback, reasonCodes, modelCalls)`. Typed constraints override the proposal field by field. The model is called with prompt `query-planner-v1`; on a failed call, invalid output, unknown operation/metric, invalid window, or a merged plan that violates the `QueryPlanV2` contract, `ruleBased` is used (operations from constraints, else keyword choice among allowlisted operations; the question supplies no parameter). Reason codes `planner_model_plan_used`, `planner_fallback_used`, `planner_model_failed_<code>`, `planner_proposal_unknown_operation`, etc. Limits: `resultCount` default 10, clamped to `min(rag.graph.max-results, 100)`; `pathDepth` default `rag.graph.max-depth`, clamped to 6.

**Resolver.** `resolve(plan): ResolutionResult(entries: List[NameResolution], evidence)`; `allResolved`, `subjectIds`, `abstainEntries`. Candidates come from the `researcher-profile-v1` index (name embedded, top 100 all-time hits) and are VERIFIED against `identity-clusters` (display name, DBLP keys), `mention-researcher` (first 3 mentions map back to the cluster) and `researcher-metrics` all-time (in graph). Similarity never decides identity. A plain name matches clusters whose display name or DBLP key equals it (exact) or equals it once a trailing 4-digit homonym suffix is removed (suffix-only); a suffixed name matches exact keys only. More than one match: `Ambiguous`, all candidates returned. One suffix-only match: `Ambiguous` (`homonym_suffix_required`). One exact match: `Resolved` when confidence >= 0.8 and in graph, else `Unresolved` (`low_confidence`). Confidence: base 0.95 `dblp_person_exact`, 0.85 `accepted_link_component`, 0.40 `unresolved_singleton`, 0.50 other; +0.04 when all checked mentions map back else -0.20; x0.6 for suffix-only; -0.30 when cannot-link status is not `clear`; at most 0.40 when not in graph. Truncation: when the name query returns a full top-100 AND its lowest-ranked hit is itself a match for the name (so more matches may rank beyond it), a name-only single match is `Ambiguous` with `candidates_truncated` (a researcher ID supplied by the caller bypasses this); more than one match carries the code as well. If the lowest hit is not a match, the ranking has left the name behind and the single match resolves normally (without this refinement every name in an index of 100 or more profiles would abstain). Recall limit: a name outranked by more than 100 profile documents that are all matches is reported as truncated, never resolved.

**Metrics.** `metrics(subjects, window)`, `windowSummary(window)`, `ranking(scope, window, field, secondary)`, `temporal(subjects, window, comparison)`. Values are copied from stored items; none is rounded, summed or derived. Each fact carries `provenanceRunId`, `policyVersion` and the stored `payloadHash` (as the input checksum). Rankable metrics: `degree` (`coauthorCount`), `weighted_degree`, `bridge_score` (`crossCommunityDegree`); others are reported as missing evidence.

**Paths.** `directCollaborators(subject, window, limit)` and `shortestPath(from, to, window, depth)` return `GraphOutput(stage, ids)`. A returned path is checked (endpoints, length 1..depth, `hops = length+1`, no repeats) and every hop edge is re-read with the `coauthor-edge` template and must carry the same edge ID; otherwise the path is dropped and reported (`path_rejected`). Hop facts: `hops`, `edgeIds`, `hopWeights` (jointPublicationCount), `hopWorkIds` (from `coauthor-edge-works`, at most 20 per edge, `worksTruncated` flag), first/last years. No path found is a fact (`found=false`) plus missing evidence.

**Community.** `component`, `community`, `degreeVsBridge`, `compare`. `degree_vs_bridge` states `coauthorCount`, `crossCommunityDegree`, `crossShare` = cross/coauthors (6 places), `classification` by rule `v1`: `bridge` if crossShare >= 0.5 and cross >= 2; `local_hub` if coauthors >= 5 and crossShare < 0.2; else `mixed`. Neighboring communities are not available through the allowlisted templates (none returns `COMMUNITY_LINK`); the stage says so as missing evidence instead of inventing them.

**Semantic.** `search(queryText, documentTypes, window, topKPerType): SemanticOutput(stage, items, skipped)`. Hit text is read through `textS3Uri` from the `ObjectStore` and checked against `textHash`; a mismatch or missing object skips the hit.

**Evidence builder.** Item text is the canonical fact JSON (keys sorted); `contentHash` = SHA-256 of text; ID = `Ids.evidenceId(type, sourceEntityId, sourceVersion, contentHash)`; provenance inputs = stored table and key, version, payload hash; runId = Spark run when valid. Bound `rag.evidence.max-items`; deterministic evidence first.

**Synthesis.** Prompt `answer-synthesis-v1`; output claims `{text, evidenceIds, assertions[{kind, subject, window?, field, value}]}`, `uncertainty`, `missingEvidence`. On model failure it falls back to `TemplateSynthesizer` (code, not a model). Claim IDs are assigned by code (`ClaimVerificationAgent.claimIdOf`).

**Verification (deterministic).** The reasoning is structural and uses only the bundle. Design: free model wording is checked by tying each token of the text to an assertion; the template synthesizer's wording (code) satisfies every rule by construction. The text is first compacted (every entity reference, stored display name of a cited identity fact and window label becomes one placeholder character). Rules, in the order the code applies them:

Decide `unsupported` / `conflicting`:
1. cites >= 1 evidence ID and all exist (`no_evidence_cited`, `unknown_evidence_id`);
2. every entity reference occurs in the text of a cited DETERMINISTIC item or is the source entity of a cited item (`reference_not_in_cited_evidence`); semantic excerpts never supply a reference;
3. every `YYYY-YYYY` window in the text occurs in a cited fact and equals the window of one of the claim's assertions or a window value they state, e.g. `prevWindow` (`window_not_in_cited_evidence`, `window_not_bound_to_assertion`);
4. every assertion matches a cited deterministic fact of the same kind, subject and exact window (a window-less assertion matches only a window-less fact): equal value is fine, different value `conflicting` (`assertion_value_mismatch`), absent fact or field `unsupported` (`assertion_without_evidence`, `assertion_field_absent`);
5. every number in the text, as digits or as a number word ("twelve", "dozen"), is bound to an assertion: it states exactly that number, its field is the one named by the nearest wording (a fixed field lexicon such as "coauthors", "average team size", "component", with a direction: "12 coauthors" vs "component 4"; within 30 characters), refined by position and qualifier ("from 8 to 12 coauthors" is previous then current, `prevCoauthorCount` only by that position or a "previous/prior/earlier" word; "average" vs "maximum/largest" team size, and a team-size number with no qualifier is not bound), its window is one the text uses, and its subject is the OWNER. A researcher-subject assertion needs that researcher as owner (the nearest preceding researcher mention, or the only researcher mentioned). Any other subject has no wildcard: the owner must be among the researchers the assertion is about (embedded in its subject, or named by an assertion on the same kind and subject: researcherA/B, from/to, hops, order, coauthorIds); a number with no owner in a text that mentions several researchers must have all of them among those (the path `length` before its arrow chain); a joint publication count needs both researchers of the pair before the number. With several researchers mentioned there is no `mentioned` fallback: an unowned number is unsupported. A digit run inside an ID, a name, a label or a hop label ("hop 2") never covers a number. Ranking values are bound by position next to each ranked researcher (`number_without_matching_assertion`);
6. path hop order written with arrows must equal the asserted `hops` (`conflicting`, `hop_order_mismatch`); an edge ID or work ID stated for a specific hop ("first hop", "hop 2", "last hop", or right after the endpoints of an arrow) must equal that hop's asserted `edgeIds` entry or be one of its `hopWorkIds` (`conflicting`, `hop_evidence_mismatch`; `unsupported`, `hop_evidence_not_asserted` when the claim does not assert them);
7. a claim citing only semantic items carries no number, assertion or window and is at best `partially_supported` (`semantic_context_only`);
7a. closed wording (claims that cite deterministic evidence). Negation ("not", "no", "never", "neither", "nor", "none", "without", any `...n't`) must be bound to an assertion that states it: "no path ... found" to `path.found=false`; negated bridge or hub wording to `classification`. Unbound negation is `unsupported` (`negation_without_assertion`); negation that a true assertion contradicts is `conflicting` (`negation_contradicts_assertion`: "no path" vs `found=true`, "never coauthored" vs a coauthor-edge, neighborhood, path or ranking assertion). Bridge and hub wording is bound to `classification` (`bridge`, `local_hub`, other; positive wording needs the matching value, negated wording ("not", "neither/nor", "rather than") needs a different value; `classification_contradicts_assertion` is `conflicting`, `classification_not_asserted` is `unsupported`). Ordinal and superlative wording (first, second, third, last, top, highest, lowest, most, least, largest, smallest, best, strongest, ...) is bound to an assertion: attached to a researcher it must match that researcher's place in the asserted ranking `order` or neighborhood `coauthorIds` (`conflicting`, `rank_wording_contradicts_assertion`, when the researcher is in the list at another place; `unsupported`, `ordinal_without_assertion`, otherwise); a list descriptor ("highest first:") needs descending ranking values or a neighborhood list; a `largest/maximum team` phrase needs the matching `max*` assertion;
7b. a display name written beside a researcher ID is that ID's stored name, else `conflicting` (`display_name_mismatch`); a pairwise relation claim (two or more researchers and "coauthored", "are coauthors", "path", "between", "via", ...) whose researchers are not all covered by a coauthor-edge, neighborhood, path or ranking assertion, or that has an uncovered reference or no assertion, is `unsupported` and removed (`relation_without_assertion`, `reference_without_assertion`).

Cap at `partially_supported` (claims that cite deterministic evidence; only `unverified_proper_noun`, `qualitative_wording_unchecked`, `reference_order_mismatch`, `text_not_anchored_to_assertion` and the non-pairwise forms of rules 8 and 11 remain partial):
8. every entity mention (an ID, or a stored display name) is covered by an assertion as its subject or inside its value (`reference_without_assertion`; on a pairwise relation claim this is `unsupported`, rule 7b);
9. a capitalized word inside a sentence that is not a stored name of a cited identity is an unverified proper noun (`unverified_proper_noun`);
10. entities appear in the order of every asserted list (`reference_order_mismatch`);
11. a pairwise relation word ("coauthored", "are coauthors", "path", "between", "via", ...) with two or more researchers needs a coauthor-edge, neighborhood, path or ranking assertion covering all of them; relation wording (bridge, community, component, path, coauthor, publication, team, identity) needs an assertion of a kind that can state it (`relation_without_assertion`; `unsupported` on a pairwise relation claim, rule 7b);
12. the text is anchored by at least one covered reference or bound number (`text_not_anchored_to_assertion`); a claim with no assertion is capped (`reference_without_assertion`, or `qualitative_wording_unchecked` when it mentions no entity).

VERIFIED therefore means: no rule above fired. LLM check (`llmVerification = true`, prompt `claim-verification-v1`) is sent only claims that passed, and the final status is the more severe of the two; a deterministic `unsupported`/`conflicting` is never sent or changed; failure of the call leaves the deterministic status. `unsupported` and `conflicting` claims are removed from the answer and kept in the audit. Capped (partial) claims stay in the answer with confidence 0.5.

Template synthesizer changes that go with these rules: it asserts `neighborhood.jointPublicationCounts`, `path.edgeIds`, `path.from`/`path.to`, `temporal_change.prevWindow`; the path sentence is written as a single arrow chain (no separate from/to mention); the window summary says "members"; supporting works are written only when the list is complete (and then asserted).

Known limits: the field lexicon, the relation families and the negation, ordinal and qualifier lists are English wording lists, not understanding (a negation or superlative phrased with a word outside the lists is not seen); hop-specific checks cover "Nth hop", "hop N", "last/final hop" and the references right after arrow endpoints, not other phrasings; a metric of the right owner with the right number but a wrong qualifier outside the fixed qualifier words is not told apart; ownership uses the nearest preceding researcher, so a sentence that puts a number before its researcher ("2 coauthors: Ada") with several researchers mentioned is unsupported, never guessed; a name without its ID in the text counts as a mention only when the cited identity fact states it uniquely; texts with other capitalized words (acronyms, product names) are capped at partial; a relation phrased with none of the listed words and with no reference or number is caught only by the optional LLM check; assertions can only state what the retrieval stages put in the bundle.

**Audit.** See section 5.

## 4. ClaimVerificationStatus to `VerificationStatus` (v1) mapping

`ClaimVerificationAgent.toV1`: `verified` to `supported`; `partially_supported` to `partially_supported`; `unsupported` to `unsupported`; `conflicting` to `contradicted`. (`unverified` is never produced.) `AnswerClaim.confidence` is 1.0 for verified and 0.5 for partially supported (a fixed convention, not a probability). Only verified and partially supported claims enter `AnswerResponse.claims`.

## 5. Key-value tables, keys and attributes

`AnalyticsReader` reads (read-only) with the layout of storage's `AnalyticsRepository`: item key `pk` = `encodeComponent(pk)` (`%` to `%25`, then `|` to `%7C`), `sk` = components encoded and joined with `|`; attributes `payload` (canonical JSON text of the typed attributes) and `payloadHash` (SHA-256 of `payload`, verified on every read; mismatch is `integrity-mismatch`). Default physical names `RuntimeTables.defaults` = `scholarchain-analytics-<logical>`; pass the configured names as `RuntimeTables(analytics = ...)`.

| Logical table | pk | sk | Used by |
|---|---|---|---|
| `researcher-metrics` | researcher ID | window label | resolver (in graph), metrics, community |
| `window-summary` | window label | none | metrics (max team size) |
| `temporal-changes` | researcher ID | window label | metrics.temporal |
| `identity-clusters` | researcher ID | none | resolver |
| `mention-researcher` | mention ID | none | resolver |
| `coauthor-edge-works` | edge ID | work ID | paths (supporting works) |

Written by `AuditAgent` (layouts of storage's `QuerySessionRepository` and `EvidenceBundleRepository`):

| Table (default) | Key | Item |
|---|---|---|
| QuerySession (`scholarchain-QuerySession`) | `pk = session-<first 40 hex of digest(queryId, run start millis)>` | `payload` = `QuerySessionRecord` JSON, `payloadHash`, `status`, `expiry` (TTL text), TTL attribute. `received` written first with `NotExists`; final state written with condition `status = received`; identical = `unchanged`, different = `conflict`, never overwritten. Retention 7 days |
| EvidenceBundle (`scholarchain-EvidenceBundle`) | `pk = queryId`, `sk = SHA-256(bundle JSON)` | `payload` + `payloadHash`, `NotExists`; above 300,000 bytes spilled to the object store (`payloadUri` + hash) |
| object store | `s3://<auditBucket>/<auditPrefix>/<sha256(queryId)>/<sha256(audit)>.json` (default bucket `scholarchain-local-audit`, prefix `rag/audit`) | the `QueryAudit` JSON, `putIfAbsent`; its URI is the session `answerUri` |

`QueryAudit` fields: queryId, sessionId, questionHash, plan, plannerFallback, plannerReasonCodes, resolutions (position, status, resolvedId, candidateIds, reasonCodes), resolvedIds, graphEvidenceIds, semanticEvidenceIds, evidenceBundleHash, metricVersions (policy versions), graphRunIds (Spark run IDs), prompts (id, version, prompt and schema SHA-256), modelId, modelCalls, stageLatenciesMillis, totalLatencyMillis, verifications, removedClaimIds, synthesisFallback, abstained, abstainReason, answerHash, codeVersion. The question is stored as a SHA-256 in `questionHash` and the session record; its text is not stored in the audit's own fields, but `QueryAudit.plan` (the `QueryPlanV2`) carries the normalized question text (`plan.question`, control characters replaced), so the audit object does hold it whenever planning succeeded. The test or service must create the tables with the key schemas above (an `InMemoryKeyValueStore` needs a `KvTableSchema` per table).

## 8. Fake model client scripting

```scala
new FakeModelClient(
  script   = Map((promptId, FakeModelClient.inputHash(request)) -> List(FakeReply.Json("..."), FakeReply.Fail(ModelError.Throttled("x")))),
  byPrompt = Map("query-planner" -> List(FakeReply.Json("not json"), FakeReply.Json("""{"operations":["max_team_size"]}"""))),
  responder = Some(BenchmarkResponders.responder),   // request => Option[json text]
  modelId = "fake-model-v1")
```

Lookup order: `script[(promptId, inputHash)]`, then `byPrompt[promptId]`, then `responder`, else `Left(ModelError.Failed("no scripted output ..."))`. The n-th call to a key returns the n-th reply and the last repeats. `inputHash` = `ModelHashes.inputHash(request)`: core digest of prompt ID, prompt version, schema ID/version and every user segment (kind, label, text). `requests` and `callCount` expose what was asked. Prompt IDs: `query-planner`, `answer-synthesis`, `claim-verification`. `BenchmarkResponders.responder` derives: planner = operations of the `structured_constraints` segment; synthesis = `TemplateSynthesizer` over the `retrieved_evidence` segment; verification = `verified` for every claim in `claims_to_check`. No model writes any benchmark value.

## 10. Building the workflow over fakes (for the composed run)

Core ports from storage's fakes: `InMemoryKeyValueStore(schemas)` (a `KvTableSchema(hasSort)` for each table in section 5: analytics tables per `AnalyticsRepository.schemas(tables)`, QuerySession `KvTableSchema(false)`, EvidenceBundle `KvTableSchema(true)`), `InMemoryVectorStore` loaded from `vectors.jsonl`, `FileObjectStore` over `embedding-runs/L4/objects` plus an empty audit bucket, a `GraphStore` over the Neptune CSVs, and `LocalHashEmbedder` (1024) for the embedder.
* Load L4 DynamoDB JSONL (`modules/storage/target/loads/L4/dynamodb/items/<table>.jsonl`): each line is `{"attributes":{...},"payloadHash":..,"pk":..,"sk":..,"table":..}`; `pk` and `sk` are already component-encoded: write `KvItem(KvKey(pk, sk-or-None), Map("payload" -> compactJson(attributes), "payloadHash" -> sha256(payload)))` into the physical table. Use `AnalyticsRepository.putAll` over `AnalyticsItems` when available, or build the items directly; the payload must be hashed with `Hashing.textHash` of the exact stored string (the runtime re-hashes it).
* The `GraphStore` must serve `neighbors`, `coauthor-edge`, `shortest-path`, `component`, `community` with the row columns the templates return (storage `GraphTemplateCatalog`): neighbors `researcherId` + `edgeId, window, jointPublicationCount, firstCollaborationYear, lastCollaborationYear, supportingWorksDigest`; coauthor-edge the same without `researcherId`; shortest-path `hops` (list of researcher IDs), `edgeIds`, `length`; component `componentId, size, window`; community `communityId, size, method, window, internalEdgeCount, crossEdgeCount`. Rows come from `COAUTHORED_WITH.csv` (undirected, `window:String` filter), `IN_COMPONENT.csv`/`Component.csv`, `MEMBER_OF.csv`/`Community.csv`. Honor `bounds.maxResults` and `maxHops`.
* `RuntimeSettings` from `RuntimeConfigLoader.load(env = Map.empty)` (set provider `fake` through `overrides = Map("scholarchain.rag.model.provider" -> "fake")` (override names are `scholarchain.` + the key; environment names are `SCHOLARCHAIN_RAG_<KEY>`) or `RuntimeConfigLoader.resolve`). `PromptRepository.locate()` finds `prompts/` from `modules/services` (walks up to the repository root).

## 11. Known limitations and not run

* The composed workflow was compiled but NOT run end to end by rag-engineer: `rag` has no store fakes and test sources belong to test-engineer; the composed run is test-engineer's work order C.
* The benchmark expectations depend on the resolver finding each name in the top 100 vector hits of the local hash embedder; a miss is an abstention to be reported, not hidden.
* `entity_filter` (topic, venue, institution) and neighboring communities are not available through the six graph templates; the workflow says so as missing evidence and offers semantic context only. Institution questions have no affiliation data (Phase 06 produced no `AFFILIATED_WITH` edges).
* Bedrock Converse and Anthropic Messages request/response shapes are NOT run against the live services; the Bedrock tool-use document conversion and the Anthropic `tool_use` parsing are verified only by compilation and, when tests are written, by fakes.
* The LLM verification prompt is optional and off by default. With the default (`llmVerification = false`) the deterministic rules above are the only checks of free model wording, so a phrasing outside the closed lists can reach the answer as `supported`; the benchmark uses template wording and does not exercise that.
* Resolver residual (review deviation (a), accepted with note): the M2 narrowing of the truncation rule means a homonym that is ranked below non-matching profiles in a full top-100 hit list is missed. The local hash embedder makes this benign; with a production embedder (Bedrock Titan or similar) similarity ranks differ, so the rule must be re-measured on the real index before the abstention behaviour is trusted. Not run here.
* L7 (deferred): `refPool` still includes the `sourceEntityId` of semantic items; an assertion on a deterministic fact is still required, so the impact is limited. L2, L3, L5 and L6 are also deferred (see `docs/agent-runs/phase-09-runtime-agents/repair-02.md`).
* `Fixed` clock gives zero latencies; with the system clock latencies are real and a re-run differs in `latencyMillis` and `totalLatencyMillis` of the audit only.
